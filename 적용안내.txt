PRO 이용 안내 팝업 통합 수정본 / 운영 서버 미반영

파일 6개를 사이트 루트의 같은 위치에 설치합니다.
수정: building_manager.php, subscribe_page.php, toss_billing_return.php
추가: pro_subscription_popup.js, pro_subscription_popup.css, pro_card_auth.php
기존 파일은 먼저 웹 공개 폴더 밖에 백업하세요.

흐름:
PRO 이용 안내 클릭 → 중앙 팝업 → 카드 등록 버튼 → 별도 토스 인증창
→ 등록 결과를 원래 팝업에 반영 → 요금/자동갱신 동의 → 결제
→ 팝업 안에서 결과/구독 상태 확인 → 닫으면 메인 PRO 상태 새로고침.
카드 인증창을 열어도 별도의 구독 페이지로 이동하지 않습니다.
카드가 없으면 카드 관리가 펼쳐지고 결제 버튼은 비활성화됩니다.
카드 등록만으로 결제하지 않으며 결제는 사용자가 별도로 누릅니다.

모바일/인증창:
토스 가이드상 모바일 iframe 안에서 결제 인증을 호출하지 않습니다.
인증은 별도 최상위 창/탭의 '카드 인증 시작' 버튼으로 시작합니다.
모바일 브라우저에서는 보안창이 새 탭으로 표시될 수 있습니다.
성공/실패 후 기존 창이 살아 있으면 알림을 보내고 닫습니다.
브라우저가 원래 창 연결을 끊었다면 'PRO 이용 안내로 돌아가기'로
빌딩매니저의 PRO 팝업을 다시 엽니다.
팝업 차단 시 허용 후 다시 시도하도록 안내합니다.
인증 결과 메시지에는 authKey, billingKey, 카드정보를 담지 않습니다.
원래 iframe은 메시지의 출처와 창 객체를 모두 확인합니다.

기존 결제 서버 로직:
연 59,000원, 자동갱신 동의, CSRF, 본인 계정 확인은 유지합니다.
annual_billing_engine.php, toss_billing.php 및 결제 키는 변경하지 않았습니다.
결제/환불/갱신 결과 후 팝업 모드가 유지되도록 리다이렉트 문맥을 보존합니다.
결제/문의 폼의 중복 클릭을 막습니다. 실제 결제의 중복 방지는 기존 서버 로직이 담당합니다.

검증:
PHP 문법과 외부 JS 구문 검사 통과.
가상 결제 함수로 카드 없음/있음, CSRF 실패, 동의 누락, 결제 성공,
카드 등록 성공, 구매자 불일치 검증 통과. 실결제/실카드 등록은 하지 않았습니다.
로컬 모의 화면에서 중앙 팝업 열기, 카드 없음 상태, 결제 버튼 비활성화,
닫기 후 원래 링크로 초점 복귀 확인.
실제 토스 테스트 상점에서 카드 등록 → 복귀 → 결제 → 취소 경로와
아이폰/안드로이드의 인증창 복귀를 추가 확인한 후 운영에 사용하세요.
